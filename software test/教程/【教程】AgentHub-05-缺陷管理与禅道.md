> 配套文件：`docs/缺陷清单_禅道导入.md`（7 条现成缺陷，三种工具都能用）、`docs/缺陷报告.md`（正式报告）

## 第 0 章 名词词典（三种工具通用 + 各自特有）

### 通用概念（三种工具都有）

| 名词 | 大白话 | 类比 |
| --- | --- | --- |
| **缺陷 Bug** | 产品里"不对的地方"——按钮点了没反应、功能和说好的不一样 | 像"充不进电"这个质量问题 |
| **严重程度 Severity** | 缺陷有多严重——P0 全挂、P1 部分挂、P2 体验差 | "充不进电=不能用"（P0）vs "后盖划痕=能但不好看"（P2） |
| **状态流转** | 缺陷从"发现"到"修好关闭"要经过的步骤 | 像快递：下单→发货→签收 |
| **回归验证** | Bug 修完后，确认它真的修好了、而且没把别的功能搞坏 | 修完充不进电后，不仅要确认能充，还要确认 Wifi/屏幕没搞坏 |
| **关联模块** | Bug 属于哪个功能——登录、对话、定时任务、管理后台 | 像手机的"屏幕"、"电池"、"摄像头" |

### 禅道特有概念

| 名词 | 大白话 |
| --- | --- |
| **产品 Product** | 你做的东西的统称——AgentHub 就是一个产品 |
| **项目 Project** | 产品的一次迭代——AgentHub v5.0 就是一个项目 |
| **模块 Module** | 产品的功能分区——登录注册、对话、定时任务 |

### Jira 特有概念

| 名词 | 大白话 |
| --- | --- |
| **Issue** | Jira 里一切工作项的统称——Bug、任务、需求、改进都叫 Issue |
| **Issue Type** | Issue 的类型：Bug=缺陷、Story=需求、Task=普通任务、Epic=大需求 |
| **Project Key** | Jira 项目的代号，AgentHub 可以叫 AHUB，Issue 编号就是 AHUB-1、AHUB-2 |
| **Sprint** | 迭代/冲刺——Scrum 里两周一迭代，每个 Sprint 里放一批 Issue |
| **Workflow** | 状态流转的规则——Jira 可以自定义每个 Issue Type 有哪些状态、谁能改 |
| **Filter** | 过滤器——保存一个搜索条件，比如"所有未关闭的 Bug"，以后一键查 |

### 飞书多维表格特有概念

| 名词 | 大白话 |
| --- | --- |
| **Base** | 多维表格本身——相当于一个轻量数据库 + 电子表格的结合体 |
| **表 Table** | Base 里的一张表——缺陷表、需求表、用例表可以放同一个 Base 里 |
| **字段 Field** | 表里的一列——标题、模块、状态、严重程度都是字段 |
| **视图 View** | 同一张表的不同看的方式——表格（Excel 样子）、看板（左右拖拽卡片）、表单（别人填的入口） |
| **自动化 Automation** | 触发器——"当缺陷状态变成已关闭时，发飞书消息通知我" |

## 第 1 章 禅道（国产开源，适合中小团队内网部署）

> 
> 为什么用禅道？**免费、全中文、数据自己掌控**，小团队不想买 Jira 不想用飞书，禅道是国产首选。面试时说"本地禅道 + 在线版切换用"显得灵活。

禅道有 **三种安装方式**，根据你自己的情况选——面试时说清楚"三种方式我都能搞，根据团队情况选"，比只说"我用一键包"加分多了。

| 方式 | 难度 | 耗时 | 适用场景 |
| --- | --- | --- | --- |
| **A. 一键包** ⭐（推荐） | 极低 | 10 分钟 | 小白、自己电脑用、面试 Demo |
| **B. 手动配环境** ⭐⭐⭐ | 中等 | 1~2 小时 | 面试想加分、公司内网部署、想掌握 Apache+PHP+MySQL |
| **C. 在线版（zentao.net）** ⭐ | 零 | 30 秒 | 不想装任何东西、临时演示 |

### 1.1 安装方式 A：一键包（推荐，小白首选）

浏览器打开禅道官网 **[https://www.zentao.net/download.html**](https://www.zentao.net/download.html**) → 找"**开源版 → Windows 一键安装包**"下载（文件类似 `ZenTaoPMS.18.x.x.win64.exe` 或 `.7z`，300MB 左右）。

> 
> 如果官网慢，清华镜像：[https://mirrors.tuna.tsinghua.edu.cn/zentao/](https://mirrors.tuna.tsinghua.edu.cn/zentao/) 找对应版本。

解压到 **`D:\zentao\`**（**路径不能有中文不能有空格！** 别放 `C:\Program Files\` 或 `D:\工具\禅道\`）。

解压后目录：

```
D:\zentao\
├─ app\          ← 禅道代码
├─ bin\          ← start.bat / stop.bat 启动脚本
├─ mysql\        ← 自带 MySQL 数据库（已经编译好，不用你装）
├─ apache\       ← 自带 Apache（已经配好，不用你装）
└─ php\          ← 自带 PHP（已经配好扩展）
```

双击 `D:\zentao\bin\start.bat`（或 CMD 里跑 `start.bat`），会弹出两个黑色窗口——一个是 Apache，一个是 MySQL。**别关它们**，关掉禅道就停了。等 5~10 秒，看到窗口里没报错、光标在闪，启动成功。

浏览器访问 **[http://localhost:8080](http://localhost:8080)**，第一次打开是安装向导：

```
第 1 步：授权协议 → 我接受
第 2 步：环境检查 → 全部打勾（一键包已经配好了）→ 下一步
第 3 步：安装模式 → 全新安装
第 4 步：数据库配置 → 全部默认（MySQL 已经在 start.bat 里配置好了 root 账号）→ 下一步
第 5 步：管理员账号 → admin / admin123（记牢，自己设的）
第 6 步：完成
```

> 
> ⚠️ **8080 端口被占了怎么办？** 打开 `D:\zentao\bin\apache\conf\httpd.conf`，搜 `Listen 8080` 改成 `Listen 8888`，重跑 `start.bat`，访问 `[http://localhost:8888](http://localhost:8888)`。

**每次启动/关闭：**

```
rem 启动
cd /d D:\zentao\bin
start.bat

rem 关闭（关黑窗口也行，但 stop.bat 更干净）
cd /d D:\zentao\bin
stop.bat
```

> 
> 💡 开机自启：每次开机都要手动跑 start.bat 烦？右键 start.bat → 发送到 → 创建快捷方式 → 把快捷方式扔到 `C:\Users\你的用户名\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\` 里。下次开机自动启。

### 1.2 安装方式 B：手动配 Apache + PHP + MySQL（进阶，面试加分）

> 
> 为什么要学这个？**一键包本质就是别人帮你配好了 Apache + PHP + MySQL，三个软件套在一个目录里**。手动配一次，你就真的懂了"Web 应用怎么跑起来"——面试问"禅道一键包你知道里面是什么吗"、"Apache 和 Nginx 什么区别"、"PHP 扩展怎么开"，你都能答。**大厂面试官特别喜欢问"你理解原理吗"，手动配过就是最好的证明**。

#### 你要装的东西（4 个）

| 软件 | 版本要求 | 下载地址 | 安装到 |
| --- | --- | --- | --- |
| Apache | 2.4.x（VC17 运行库） | [https://www.apachelounge.com/download/](https://www.apachelounge.com/download/) | `D:\apache24\` |
| PHP | 7.4.x（禅道 18.x 要求 7.1~7.4，不兼容 8.0+） | [https://windows.php.net/download/](https://windows.php.net/download/) 选 "Thread Safe x64 zip" | `D:\php74\` |
| MySQL | 5.7 或 8.0 | [https://dev.mysql.com/downloads/installer/](https://dev.mysql.com/downloads/installer/) | 默认即可（推荐 8.0） |
| 禅道源码 | 和一键包同版本 | [https://www.zentao.net/download.html](https://www.zentao.net/download.html) 找 "源码包"（.zip） | `D:\zentao-src\` |

#### 第一步：装 MySQL（最简单，有图形向导）

1. 下载 MySQL Installer（`mysql-installer-web-community.msi`，小文件，会边下边装）
2. 双击 → 选 "Server only"（只装 MySQL Server，够了）→ 一路 Next
3. 类型选 "Development Computer"（开发机，够用了）→ Next
4. **重要**：设置 root 密码（比如 `root123`，记牢）→ Next
5. 一路 Execute → Finish
6. 验证：CMD 跑 `mysql -u root -proot123`，能进 MySQL 命令行就行

> 
> 💡 如果你已经有 MySQL（比如项目自己那套），直接用就行——禅道可以共用同一个 MySQL 实例，只要在里面建一个新数据库。

#### 第二步：装 PHP（解压缩就行）

1. 下载 PHP 7.4 **Thread Safe x64 zip**（不是 Non Thread Safe，不是 8.x！）
2. 解压到 **`D:\php74\`**
3. 开 PHP 配置：复制 `D:\php74\php.ini-development` 重命名为 **`php.ini`**
4. 打开 php.ini，找到 `;extension_dir = "ext"` 那行，改成：
   ```ini

   extension_dir = "D:\php74\ext"
   ` 5. 找到 \`; extension =\` 这一堆（大概 900 多行），**把下面 8 行前面的分号去掉**（分号是注释，去掉就是启用）：    `ini
   extension=mysqli
   extension=pdo_mysql
   extension=gd
   extension=mbstring
   extension=openssl
   extension=curl
   extension=fileinfo
   extension=zip
   ```
6. 保存。验证：CMD 跑 `D:\php74\php.exe -v`，能显示版本号就行。

#### 第三步：装 Apache（解压缩 + 改配置）

1. 下载 Apache Lounge 的 VC17 版本（**必须先装 VC17 运行库**——[https://aka.ms/vs/17/release/vc_redist_x64.exe](https://aka.ms/vs/17/release/vc_redist_x64.exe)，双击装一次就行）
2. 解压 Apache 到 **`D:\apache24\`**
3. 打开 `D:\apache24\conf\httpd.conf`，改三处：
   - **第 1 处**：搜 `Define SRVROOT`，改成：
     `apache      Define SRVROOT "D:/apache24"      `
   - **第 2 处**：文件**最末尾**加一段（配 PHP 模块 + 默认加载 index.php）：
     `apache      # PHP 模块      LoadModule php7_module "D:/php74/php7apache2_4.dll"      PHPIniDir "D:/php74"      AddHandler application/x-httpd-php .php      DirectoryIndex index.php index.html      `
   - **第 3 处**：搜 `Listen 80`，如果 80 端口被占（比如 IIS 或别的东西），改成 `Listen 8080`
4. 验证配置：CMD 跑：
   ```cmd

   D:\apache24\bin\httpd.exe -t
   ```
   显示 `Syntax OK` 就是对的。如果报错"LoadModule php7_module 找不到"，说明你 PHP 下载的是 Non Thread Safe 版本，换 Thread Safe 重下。

#### 第四步：部署禅道源码 + 配 VirtualHost

1. 下载禅道源码包（.zip），解压到 **`D:\zentao-src\`**（里面应该有 `zentao\` 子目录）
2. 开 `D:\apache24\conf\httpd.conf`，文件末尾**再加一段**（VirtualHost 让 Apache 知道哪个域名/端口对应禅道）：
   ```apache

   <VirtualHost *:8080>
       ServerName localhost
       DocumentRoot "D:/zentao-src/zentao"
       <Directory "D:/zentao-src/zentao">
           AllowOverride All
           Require all granted
       
   
   ```
3. 验证：`httpd.exe -t` 要显示 Syntax OK
4. **启动 Apache**：CMD 跑 `httpd.exe`（或者装成 Windows 服务：`httpd.exe -k install`，然后 net start Apache2.4）。启动后没有任何输出（成功不说话），浏览器访问 [http://localhost:8080](http://localhost:8080) 能看到禅道安装向导就行。

#### 第五步：创建 MySQL 数据库 + 走完安装向导

浏览器访问 [http://localhost:8080](http://localhost:8080) 或你改过的端口，和一键包的安装向导**几乎一样**，只有一个区别——**第 4 步数据库配置你要自己填**：

```
数据库主机：localhost
数据库端口：3306（MySQL 默认）
数据库用户：root
数据库密码：root123（你第二步设的那个）
数据库名：zentao（新建一个，向导会帮你建）
```

走完向导，禅道跑起来了。

#### 方式 A 和方式 B 对比

| 维度 | A. 一键包 | B. 手动配 |
| --- | --- | --- |
| **耗时** | 10 分钟 | 1~2 小时（主要折腾版本兼容） |
| **版本坑** | 无，全部预配好 | PHP 必须 7.4、Apache 要 VC17、MySQL 5.7+ |
| **能学到什么** | 禅道本身 | Apache 配置、PHP 扩展、MySQL 建库、VirtualHost |
| **面试加分** | 够用 | ⭐⭐⭐ 面试官喜欢问"你理解原理吗" |
| **缺点** | 三个软件绑死在一起，不能单独升级 | 每次装都是一次踩坑 |

**面试话术**："我两种方式都用过。一键包平时自己用，10 分钟搞定；手动配那个我专门练过一次——PHP 7.4 + Apache 2.4 + MySQL 8.0，改了 httpd.conf 的 LoadModule、PHPIniDir、VirtualHost，开了 8 个 PHP 扩展（mysqli、pdo_mysql、gd、mbstring...）。手动配完我真的懂了 Web 应用怎么跑起来的——Apache 监听端口、PHP 处理脚本、MySQL 存数据，这一套串起来了。"

### 1.6 手动新增一条缺陷（每条字段填什么，逐格解释）

如果自己测出来新 Bug，手动提一条，面试高频题"你怎么写 Bug 报告"。

禅道左侧【测试】→【Bug】→ "+ 新建缺陷"，逐格填：

| 字段 | 填什么 | 怎么选 | 本项目例子 |
| --- | --- | --- | --- |
| 所属产品 | 刚才建的 | 下拉 | 灵枢 AgentHub |
| 所属项目 | 刚才建的 | 下拉 | 灵枢AgentHub V1.0系统测试 |
| 所属模块 | Bug 在哪个功能 | 下拉 | 管理后台 |
| **标题** | **一句话说清楚问题** | —— | admin 删除用户传 uid=999 也返回 200 |
| 严重程度 | 有多严重 | 下拉（见分级） | P1-重要 |
| 打开版本 | 哪个版本测出来的 | 下拉 | preview |
| 指派给 | 让谁修 | 下拉 | admin |

**严重程度怎么选（面试高频，必须背）**

| 等级 | 意思 | 本项目例子 |
| --- | --- | --- |
| P0 致命 | 核心功能完全不可用、系统崩了 | BUG-002 定时任务到点直接报错，整个功能不可用 |
| P1 重要 | 核心功能有问题、权限问题、数据不一致 | BUG-009 admin 删用户不查存不存在，uid=999 也返回成功 |
| P2 一般 | 功能能用但体验差、文案不对 | BUG-004 注册完还要手动再登一次 |
| P3 建议 | 优化建议，不算 Bug | （本项目没 P3） |

**好 vs 差的 Bug 报告对比**

|  | ❌ 差的（开发视角） | ✅ 好的（测试视角） |
| --- | --- | --- |
| **标题** | `delete_user 函数没有校验 uid` | `admin 删除用户传 uid=999 也返回 200` |
| **复现步骤** | 直接写 curl 命令 | 1. admin 登录 → 2. DELETE /api/admin/users/999 → 3. 看返回 |
| **预期结果** | 返回 404 | 返回 404 "用户不存在" |
| **实际结果** | 返回 200 | 返回 200，没有任何错误信息 |
| **为什么差** | 说函数名、代码细节——开发自己知道 | 站在用户角度，说"我操作了什么、看到了什么不对" |

### 1.7 缺陷状态流转

一条 Bug 的生命历程：

```
新建 (new) → 激活 (active) → 已修复 (fixed) → 已关闭 (closed)
                ↑                    ↓
                └── 重新打开 ←── 验证失败 (reopen)
```

| 状态 | 意思 | 谁改的 | 什么时候 |
| --- | --- | --- | --- |
| **新建** | 刚提的 Bug | 测试 | 点"保存"后自动 |
| **激活** | 开发确认这是 Bug，开始修 | 开发 | 看完确认"确实是 Bug"就激活 |
| **已修复** | 开发改完代码 | 开发 | 代码提交后 |
| **重新打开** | 测试回归没过 | 测试 | 修的不对 |
| **已关闭** | 测试回归通过 | 测试 | 真的修好了 |

## 第 2 章 回归怎么跑（三种工具通用的方法论）

> 
> 不管用禅道/Jira/飞书多维表格，**回归的方法是一样的**——工具只是记录载体，回归才是真本事。面试问"修完 Bug 你只测那一个点吗"，就是考这一章。

### 2.1 P0/P1 缺陷（5 条）——交叉验证

修完不能只跑那一条用例！关联模块也要测：

| Bug | 关联模块交叉验证 |
| --- | --- |
| BUG-002 定时任务到点报错 | 复测 send 接口（调度器复用 send 链路）、定时任务全链路（建→跑→停→删） |
| BUG-001 级联删除没清干净 | 复测 admin 删用户 + 查 7 张关联表、复测删正常用户流程没被改坏 |
| BUG-009 admin 删用户漏校验 | 复测 admin 删正常用户没被改坏、复测 uid=999 返回 404、复测普通用户调删除接口返回 403 |
| BUG-007 字数上限不生效 | 复测 1 字 / 2 字 / 500 字 / 501 字四个边界 |
| BUG-005 定时任务差 8 小时 | 复测新建定时任务显示时间、到点触发时间差不超过 1 分钟 |
| BUG-006 验证码偶尔空白 | 多次刷新验证码确认每次正常、极端情况走降级路径不阻塞注册 |

### 2.2 P2 缺陷（1 条）——定向回归

修完只跑定向用例：

- BUG-004：注册完自动跳首页 + 用新账号直接发对话

### 2.3 核心模块改动后——全量回归

改了**调度器、权限校验、鉴权中间件**这些基础模块，必须跑全部 42 条 pytest 接口自动化用例 + Postman 全量，不能漏。

> 修正：和你项目匹配，你是42条pytest接口用例，不是88条

## 第 3 章 Jira 常用方法（大厂标配，Scrum/Kanban 都支持）

> 
> 为什么学 Jira？**大厂几乎 100% 用 Jira**，面试时说"我会用 Jira 的 Kanban 看板管理迭代、用 Filter 跟踪未关闭的 Bug、用 Workflow 自定义状态流转"，面试官立刻知道你有大厂思维。Jira 免费版支持 10 个用户，足够小团队用。

### 3.1 注册（30 秒）

浏览器打开 **[https://www.atlassian.com/software/jira/free**](https://www.atlassian.com/software/jira/free**) → 填邮箱 → Atlassian 发验证邮件 → 设密码 → 选 "Start project from scratch" → 选 **Kanban**（简单，不用搞 Scrum 的 Sprint）或者 **Scrum**（大厂标准） → Project Key 填 **AHUB**（AgentHub 的缩写，Issue 编号就是 AHUB-1、AHUB-2）。

> 
> 💡 **Project Key 是什么？** Jira 里每个 Issue 都有一个唯一编号，格式是 `项目代号-数字`，比如 AHUB-1、AHUB-2。这个代号要在项目创建时指定，一旦定了改不了，所以起名要想好。

### 3.2 Jira 界面长什么样

进入项目后，左侧菜单：

```
📋 项目左侧菜单
├─ Backlog        ← 需求/缺陷的"库存池"，还没排进迭代的
├─ Board          ← 看板（Kanban）或 Scrum Board（带 Sprint 的看板）
├─ Reports        ← 统计图表（缺陷趋势、燃尽图）
├─ Issues         ← 所有 Issue 的列表
└─ Project settings ← 项目设置（改状态流、改字段、改权限）
```

### 3.3 创建一个 Bug（Issue）

1. 点顶部的 **"Create"** 按钮（快捷键 `c`）
2. 弹窗里填：

| 字段 | 填什么 | 选什么 |
| --- | --- | --- |
| Issue Type | Bug | 下拉选 Bug（不是 Story/Task） |
| **Summary** | **一句话标题** | `admin 删除用户传 uid=999 也返回 200` |
| Description | 详细内容 | 复现步骤 + 预期结果 + 实际结果，用 Jira 的 markdown 格式（`h3. 复现步骤` 开头三级标题，`* 列表项` 开头列表） |
| Priority | 严重程度 | Blocker/P0/High/P1/Medium/P2/Low/P3（和禅道分级几乎对应） |
| Labels | 标签 | 可以填 `admin`（模块）+ `boundary-check`（根因类别），以后搜起来方便 |
| Assignee | 指派给谁 | 下拉选你的队友（Demo 就选自己） |

> 
> 💡 **Jira 的 Description 怎么写好看？** 它支持 Wiki 标记：`h3. 复现步骤` 是三级标题、`* 列表项` 是无序列表、`{code}` 代码块 `{code}` 是代码。但如果你只是写复现步骤，直接用纯文本列表就行，面试不说你用了 markdown 格式。

### 3.4 批量导入 7 条缺陷（CSV）

7 条缺陷一条一条 Create 太慢，Jira 支持从 CSV 批量导入：

**第 1 步：准备 CSV**

Excel 建文件，列头必须和 Jira 的字段名一致：

```
Summary,Issue Type,Priority,Description,Labels,Assignee
"admin 删除用户后，关联数据没有一起清干净","Bug","High","复现步骤：
1. admin 登录删 tester
2. 查 sessions 表还在
预期：级联清理
实际：只删 users","admin,db","你的名字"
```

> 
> ⚠️ **CSV 里有换行怎么办？** 把整个字段用双引号包起来就行，Excel 保存时默认会做这个。**必须用 UTF-8 编码**，不然 Jira 导入中文会乱码。

**第 2 步：上传**

Jira 项目设置（齿轮图标 → 项目设置） → 左侧找 "External Import" → "CSV" → 下载 CSV 模板（确保列头名对） → 上传你自己的 CSV → 映射每一列 → 确认导入。7 条 Issue 一次性进来，编号 AHUB-1 到 AHUB-7。

### 3.5 看板 Board 上的状态流转

Jira Kanban 看板默认就有三列：

```
┌──────────┬──────────────┬──────────┐
│  To Do   │ In Progress  │   Done   │
├──────────┼──────────────┼──────────┤
│ AHUB-1   │ AHUB-3       │ AHUB-6   │
│ AHUB-2   │ AHUB-4       │ AHUB-7   │
│ AHUB-5   │ AHUB-9       │          │
└──────────┴──────────────┴──────────┘
```

**怎么改状态？**

- 直接**拖拽卡片**从 To Do 到 In Progress（开发开始修了）
- 修完了拖到 Done（测试回归过了）
- 回归没过？拖回 To Do 或点卡片里的 "Reopen" 按钮

> 
> 💡 Jira 的 Workflow 可以自定义。比如你们团队想加 "Code Review" 这一列（To Do → In Progress → Code Review → Done），项目设置 → Workflows → 编辑 → 加状态 → 连 transition，就能改。面试说"我给我们团队的 Jira 自定义了包含 Code Review 的 6 状态 Workflow"，比说"我会拖拽看板"加分多了。

### 3.6 Filter（过滤器）——一键查"所有 P0 未关闭 Bug"

Jira 最常用的功能之一——保存一个搜索条件，以后点一下就出来。

**怎么建？**

1. 点左侧 "Issues"
2. 搜索框里用 **JQL**（Jira Query Language）写条件：

```
project = AHUB AND issuetype = Bug AND priority = Blocker AND status != Done ORDER BY created DESC
```

这句话的意思：**AHUB 项目里所有 P0 缺陷，还没关掉的，按创建时间倒序**。

3. 点搜索框右边的 **"Save as filter"** → 起名 "P0 未关闭 Bug" → 选 "Shared" 让团队都能用 → 保存。
4. 以后点左侧 "Filters" → "P0 未关闭 Bug"，结果一键出来。

> 
> 💡 **JQL 是 Jira 的灵魂**，面试高频题。记住几个常用的：
> 
> 
> - `project = AHUB` 某个项目
> - `issuetype = Bug` 缺陷
> - `priority in (Blocker, High)` P0 和 P1
> - `status != Done` 未关闭
> - `assignee = currentUser()` 指派给我自己的
> - `created >= "2026-10-20"` 10 月 20 号之后创建的
> - 组合起来：`project = AHUB AND issuetype = Bug AND priority = Blocker AND status != Done`

### 3.7 仪表盘 Dashboard

在 Jira 项目首页（不是 Board，是 Overview 或另开一个 Dashboard）可以挂组件：

- **Created vs Resolved 折线图**：每天新建多少 Bug、关掉多少，一眼看出项目健康度
- **Priority Pie Chart**：P0/P1/P2 各有几个
- **Filter Results**：把刚建的"P0 未关闭 Bug" Filter 直接嵌进来
- **Recent Activity**：最近谁改了什么 Issue

面试说"我在 Jira 项目首页挂了优先级饼图和 P0 未关闭列表，每天 standup 先看一眼"，显得你会用数据驱动。

### 3.8 Jira 和禅道的状态对照

| 禅道状态 | Jira 默认状态 | 说明 |
| --- | --- | --- |
| 新建 new | To Do | 刚提出来的 |
| 激活 active | In Progress | 开发开始修 |
| 已修复 fixed | Done（或 Code Review） | 代码提交 |
| 重新打开 reopen | 重新拉回 In Progress | 回归没过 |
| 已关闭 closed | Done + Resolution=Fixed | 测试回归通过 |

## 第 4 章 飞书多维表格（Base，小团队零门槛快启动）

> 
> 为什么学飞书多维表格？**不用安装、不用付费、和飞书消息/日历无缝打通**，3 人以下小团队建个 Base 5 分钟就能开始管理缺陷。而且飞书多维表格有"看板视图"可以左右拖拽 Bug 卡片，有"表单视图"可以生成链接让别人提 Bug，有"自动化"可以在 Bug 状态变化时自动通知，比禅道/Jira 都轻量。

### 4.1 创建一个 Base（多维表格）

1. 打开飞书桌面端或网页版
2. 左侧"文档" → 右上角"+ 新建" → 选 **"多维表格"**（不是表格！表格是纯 Excel，多维表格有视图和自动化）
3. 起名 **"灵枢AgentHub 缺陷管理"**
4. 进去后默认已经有一张表（叫"表1"），改名为 **"缺陷清单"**

### 4.2 给缺陷表加字段（列）

点每一列的表头（显示"字段1"、"字段2"...的地方），改名 + 选类型：

| 列名 | 类型 | 说明 |
| --- | --- | --- |
| 编号 | 自动编号 | 飞书自动生成 BUG-001、BUG-002... |
| 标题 | 多行文本 | Bug 的一句话标题 |
| 模块 | 单选 | 下拉选：登录注册、智能体、对话、定时任务、交付物、管理后台 |
| 严重程度 | 单选 | 下拉选：P0 致命、P1 重要、P2 一般、P3 建议 |
| 优先级 | 单选 | 下拉选：高、中、低 |
| 状态 | 单选 | 下拉选：新建、激活、已修复、重新打开、已关闭（和禅道一模一样） |
| 复现步骤 | 多行文本 | 1. xxx 2. xxx |
| 预期结果 | 多行文本 | 应该是什么样 |
| 实际结果 | 多行文本 | 实际是什么样 |
| 修复建议 | 多行文本 | 可选，你猜的根因或修复方向 |
| 发现日期 | 日期 | 飞书自带日期选择器 |
| 负责人 | 人员 | 从飞书通讯录里选 |

> 
> 💡 **单选字段的选项怎么加？** 点列头 → 字段属性 → 选项 → 一个个加进去。加完以后每行点一下就能选，比打字快多了。

### 4.3 导入 7 条缺陷

两种方式：

**方式 A：粘贴进去（最快）**

1. 打开 `docs/缺陷报告.md`，逐条把标题、模块、严重程度、复现步骤等复制粘贴到对应列
2. 每粘贴一条，点一下状态列选"新建"，模块选对，飞书自动分配编号

**方式 B：表单提交（更规范，让别人帮你提）**

1. 飞书多维表格 → 表名旁边点 **"视图"** → 点 **"+"** → 选 **"表单"**
2. 表单里每行是一个字段，把"编号"、"负责人"这些不公开的字段设为"隐藏"
3. 飞书自动生成一个链接（类似 `https://xxx.feishu.cn/base/xxx?table=xxx&view=form`）
4. 把链接发给队友，队友点链接就能在线提 Bug，不用进飞书

> 
> 💡 你自己可以先点表单链接提一条 BUG-009 试试，体验一下别人提 Bug 是什么感觉。

### 4.4 看板视图——左右拖拽改状态

表格视图（就是 Excel 样子的默认视图）适合看全量数据。看板视图适合看状态流转，一目了然。

**怎么建？**

1. 表名旁边点 "视图" → "+" → 选 **"看板"**
2. 飞书问你 **"按哪个字段分组？"** → 选 **"状态"**
3. 确认，看板出来了：

```
┌──────────┬──────────────┬──────────┬──────────────┬──────────┐
│  新建     │    激活       │ 已修复   │  重新打开     │ 已关闭   │
├──────────┼──────────────┼──────────┼──────────────┼──────────┤
│ BUG-009  │ BUG-001      │ BUG-002  │              │ BUG-004  │
│          │ BUG-005      │          │              │ BUG-006  │
│          │              │          │              │ BUG-007  │
└──────────┴──────────────┴──────────┴──────────────┴──────────┘
```

**改状态就是拖拽**——卡片从"激活"拖到"已修复"列，状态字段自动变成"已修复"，和 Jira 一模一样。

> 
> 💡 看板还能按**优先级**加颜色标签——P0 红、P1 橙、P2 黄，一眼看到最急的几个。点卡片 → 标签 → 选颜色，或者字段属性里预设颜色。

### 4.5 自动化——Bug 状态变了自动发消息

飞书多维表格最大的杀招：**触发器**。不用写代码，设置一下就能在条件满足时自动做动作。

**场景**：当一条缺陷的状态变成"已修复"时，自动给测试发飞书消息说"XX 缺陷已修复，请回归验证"。

**怎么设？**

1. 表名旁边点 "自动化"（或右上角闪电图标）→ "+ 新建规则"
2. **触发条件**：当记录更新时 → 选择字段 "状态" → "从" 不是 "已修复" → "变成" "已修复"
3. **动作**：发送消息 → 接收方选你自己（或指定测试）→ 消息内容可以用飞书模板：`缺陷 {{标题}} ({{编号}}) 状态变成了已修复，请回归验证`
4. 保存，给规则起名"修复通知"

以后开发把 BUG-009 拖进"已修复"列，你手机上立刻收到飞书消息："缺陷 admin 删除用户漏校验 (BUG-009) 状态变成了已修复，请回归验证"。

> 
> 💡 更多自动化场景：
> 
> 
> - 当严重程度是 "P0 致命" 时，自动发群消息 @所有人
> - 当缺陷创建超过 3 天还停在 "新建" 状态时，自动提醒负责人
> - 当你把看板的列名改成"紧急处理"时，自动把优先级改成"高"

面试说"我在飞书多维表格里设了 P0 自动通知群、修复自动通知测试的两条自动化，不用每天手动查"，比说"我会拖拽看板"高一个档次。

### 4.6 权限和分享

**公开看板**：想让产品、老板也能看缺陷进度，但不让他们改？

1. 右上角 "分享" → 链接权限设为 **"知道链接可查看"**
2. 把链接发出去，别人打开就是你那个看板视图，只能看不能改

**指定范围**：想让前端组只看前端模块的 Bug？

1. 建一个新视图（比如叫"前端组专属"）
2. 过滤器设：模块 = "对话" OR 模块 = "定时任务"
3. 分享链接给前端组，他们点进来只看到自己负责的那几个模块

### 4.7 飞书多维表格 vs 禅道/Jira 的状态对照

| 状态语义 | 禅道 | Jira | 飞书多维表格 |
| --- | --- | --- | --- |
| 刚提出来 | 新建 | To Do | 新建（单选值） |
| 开发开始修 | 激活 | In Progress | 激活 |
| 代码提交 | 已修复 | Done | 已修复 |
| 回归没过 | 重新打开 | 重新拉回 In Progress | 重新打开 |
| 测试通过 | 已关闭 | Done + Resolution=Fixed | 已关闭 |

## 第 5 章 三种工具怎么选（对比表 + 面试话术）

### 5.1 全维度对比

| 维度 | 禅道 | Jira | 飞书多维表格 |
| --- | --- | --- | --- |
| **收费** | 开源免费（企业版收费） | 免费版 10 用户，超过收费 | 免费版 3 Base，够用 |
| **安装** | 本地版要装 10 分钟，在线版免安装 | Atlassian 云版免安装，注册即用 | 零安装，飞书里直接建 |
| **中文** | 全中文原生 | 有中文但部分术语还是英文 | 全中文原生 |
| **数据归属** | 本地版自己掌控，在线版在禅道服务器 | Atlassian 云服务器 | 飞书服务器 |
| **上手难度** | 中等（概念多：产品/项目/模块） | 较高（JQL/Workflow/Sprint 要学） | **极低**（表格 + 视图 + 自动化，5 分钟上手） |
| **缺陷管理** | 专用，最强 | 专用，最强 | 够用，但不是专用工具 |
| **需求管理** | 有（产品功能列表） | 强（Epic/Story/Task 层级） | 可以但弱（用多行文本写需求） |
| **迭代/Sprint** | 有（版本迭代） | 强（Scrum Kanban 双模式） | 弱（靠分组和标签模拟） |
| **自动化** | 有 Webhook，一般 | 有 Automation，强 | **零代码自动化，最强** |
| **看板拖拽** | 有 | 有 | 有 |
| **导入导出** | CSV（需要插件） | CSV/Excel/其他工具 | 粘贴 + Excel 导入导出 |
| **权限管理** | 有（产品/项目/模块三级） | 强（角色 + 方案） | 有（按 Base/表/视图三级） |
| **和 IM 集成** | 弱（要配飞书 Webhook） | 有 Slack 插件 | **原生飞书，最强** |
| **面试加分点** | "我用国产开源，数据自己掌控" | "我会 JQL 查 Bug、自定义 Workflow" | "我设了零代码自动化，不用手动查进度" |

### 5.2 怎么选（**根据团队情况**）

| 团队场景 | 选什么 | 理由 |
| --- | --- | --- |
| 1~5 人小团队、**国产环境**、不想花钱 | **飞书多维表格** | 零门槛、免费、和飞书无缝、5 分钟建完开始干活 |
| 1~5 人小团队、**内网/私有化部署**、不想数据放外面 | **禅道本地版** | 本地 Apache+MySQL，数据全在自己电脑/服务器 |
| 20+ 人中大型团队、**需要 Scrum 迭代**、需要报表和统计 | **Jira** | 业界标准、Scrum/Kanban 都支持、有燃尽图和速度图 |
| 外包/接私活、**要给甲方交付文档**、甲方没要求具体工具 | **飞书多维表格** | 导出 Excel 或 PDF 报告给甲方，甲方打开就能看 |
| **实习简历/面试演示** | 禅道 **或** 飞书多维表格（看面试公司情况） | 国内公司禅道和飞书都熟，Jira 面试时说"学过、理解原理、上手 1 天就能用"就行 |

### 5.3 面试回答模板（三种工具的综合问答）

**问：你用什么工具管理缺陷？**

答：我三种都用过，根据团队情况选。之前那个小团队（3 人后端 + 1 人前端 + 我一个测试），我们用**飞书多维表格**——零安装、免费、和飞书消息无缝，我设了 P0 自动通知群、修复自动通知测试的两条自动化，不用每天手动查。后来那个项目要在内网私有化演示，我就用**禅道本地版**，一键包10分钟装好，数据全在本地。**Jira 我也学过**，理解原理，知道用 JQL 查 Bug、自定义 Workflow、用 Kanban 看板管理迭代——大厂基本都用 Jira，但我们那个小Demo项目体量小，禅道就足够了。

**问：飞书多维表格能当缺陷管理工具吗？**

答：**能，而且对小团队特别好用。** 它不是专门的缺陷管理工具，但够用。我建了一个 Base，缺陷表加了 12 个字段——编号自动生成、模块和严重程度用单选下拉、状态有 5 个值和禅道一模一样。看板视图按状态分组，改状态就是拖拽卡片。还设了两条自动化：P0 自动 @群、修复自动通知测试。唯一的缺点是它没有禅道/Jira 那种强制 Workflow 审批流——禅道可以约束流转权限，飞书多维表格谁都能改状态，但小团队其实不需要这么严的流程。

**问：Jira 和飞书多维表格比，强在哪里？**

答：**强在"结构化"和"流程化"。** 飞书多维表格本质还是电子表格，Jira 是专门的项目管理工具——它有 Epic/Story/Task 四层需求结构、有 Scrum Sprint 迭代、有 JQL 搜索语言能写出极复杂的查询条件、有 Workflow 能自定义每一步谁能改状态。但代价是**学习成本高**——新人要学 JQL、要理解 Sprint 和 Backlog 的区别、要知道怎么加 Workflow 状态。小团队 3 个人，Jira 用起来太重，飞书多维表格上手更快。

**问：三种工具的状态流转你能画一下吗？**

答：**三种工具语义完全一致，只是叫法和操作方式不同。** 从新建→激活→已修复→验证通过→已关闭，这个链路是行业通用的。禅道里手动编辑状态；Jira 是拖拽看板卡片；飞书多维表格也是拖拽看板。禅道有"重新打开"这个状态、Jira 是把卡片从 Done 拖回 In Progress、飞书多维表格是把卡片从"已关闭"列拖回"激活"列。工具不同，心智模型是一样的。

## 第 6 章 面试高频问答（扩展版）

### 缺陷报告怎么写（高频中的高频）

**答**：站在测试视角，不说代码细节。必须有 5 块：标题（一句话说清楚问题，不说函数名）、所属模块、严重程度（P0/P1/P2）、复现步骤（别人拿到能一步不差复现）、预期结果 vs 实际结果。截图能加就加。比如 BUG-009 我写的是"admin 删除用户传不存在的 uid=999 也返回 200 成功"，**不会**写"delete_user 函数没校验 uid"——后者是开发视角，测试不该这么写。

### P0/P1/P2 怎么定义的

**答**：P0 是核心功能完全不可用，比如定时任务到点直接报错、整个功能没法用；P1 是核心功能有问题但能临时绕过，或者权限绕过、数据不一致这种风险问题；P2 是功能能用但体验不好，比如注册完还要手动再登一次。P0 一般要求优先紧急修复，P1 要求本轮迭代修复，P2 看产品排期。

### 修完一个 Bug，你只测那一个点吗？

**答：绝对不是。** 这是测试的核心思维——**改一个点可能坏一片**。我分三档：

- **P0/P1 Bug**：跑原复现用例 + 关联模块交叉验证。比如 BUG-009 admin 删用户漏校验，我除了测 uid=999 返回 404，还要复测 admin 删正常用户没被改坏、复测普通用户调删除接口返回 403（权限校验）。
- **P2 Bug**：跑定向回归，只测那个点。
- **核心模块改动**（比如调度器、权限中间件）：跑全量 42 条 pytest 接口自动化用例 + Postman 接口用例。

**答**：**pytest+Requests 自动化脚本执行的时候发现的。** 我自动化用例里专门写了边界测试场景，调用 DELETE `/api/admin/users/999`，断言应该返回 404，脚本执行失败，捕获到这个缺陷。这个 Bug 纯手工点点点
