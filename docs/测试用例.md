> 执行日期 2026-11-03，执行环境 Windows 11 + Python 3.10.11 + MySQL 8.0，Postman 集合 `software test/postman/`

说明： 分接口测试和功能测试两部分。接口测试覆盖 24 个后端接口，按正向/反向/鉴权/越权/边界/注入六个维度设计，共 **85 条**。功能测试覆盖 8 个前端页面，用场景法 + 边界值 + 等价类 + 错误猜测四种方法设计，共 **51 条**。合计 **136 条**。

### 功能测试的用例设计方法说明

| 方法 | 含义 | 在本项目里用在哪 |
|---|---|---|
| **场景法**（主要） | 模拟用户真实操作路径，串完整链路 | 登录→新任务→对话→定时任务→管理后台，每条主链路都写了 |
| **边界值** | 卡在限制边上的值 | 用户名 2/3 字符、密码 5/6 字符、目标 500/501 字、用户列表分页 |
| **等价类** | 把输入分"有效"和"无效"两类，各挑代表 | 正确密码/错误密码/纯空格、已存在/不存在的用户名、注入词英文/中文带 emoji |
| **错误猜测** | 凭经验猜哪里容易出 bug | 连续点两次按钮重复提交、断网提示、停用再启用 toggle 语义、改目标后触发用新的、前端缓存旧数据、连续输错密码会不会锁账号 |

### 功能测试的写法原则

**功能测试 = 模拟真实用户的操作。不打开 F12，不查数据库，不调 Postman。**

- ✅ 步骤写：点哪里、填什么、等多久
- ✅ 预期结果写：用户眼睛能直接看到的现象（页面跳转、按钮变灰、提示文案、列表里有没有这条）
- ❌ 不说：接口路径（POST /api/xxx）、HTTP 状态码、表名、数据库、token、Network、HeidiSQL、调度器 job、tester_id 这些开发/测试术语
